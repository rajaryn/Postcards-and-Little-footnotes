# Postcards & Little Footnotes — Architecture

## 1. Project Overview

Postcards & Little Footnotes is a lightweight Progressive Web App for capturing small moments during a trip.

A moment can contain:

* A photo
* A caption (footnote)
* Both
* Neither is required, but a moment must contain at least one

The application organizes moments chronologically inside a trip.

The primary mental model is:

```text
User
 └── Trip
      └── Moments
           ├── Photo + footnote
           ├── Footnote only
           ├── Photo only
           └── ...
```

Days are derived dynamically from moment timestamps rather than stored as separate entities.

The application is intentionally not designed as a traditional photo gallery, cloud drive, or map-first application.

The core action is:

> Something happens → capture it → continue the trip.

## 2. Technology Stack

### Frontend

* HTML5 semantic markup
* CSS3 with custom properties and responsive fluid typography
* Vanilla JavaScript (modular architecture using singleton namespaces)
* Client-side HEIC/HEIF WebAssembly image transcoder (`heic2any.min.js`)
* PWA Web App Manifest (`manifest.json`)
* Service Worker (`service-worker.js`) caching static shell assets (cache version: `postcards-shell-v6`)
* Browser APIs: Camera capture, File API, Drag-and-Drop API, History/Hash routing, LocalStorage

No frontend framework is required.

### Backend

* Python 3.12+ (managed via `uv`)
* Flask microframework
* Flask REST-style JSON endpoints with custom JSON datetime serializer
* Authentication: `werkzeug.security` (secure password hashing) & `itsdangerous` (`URLSafeTimedSerializer` signed auth tokens)
* Image storage service: `boto3` for Cloudflare R2 presigned URLs and streaming upload fallback
* Notification Service: Standard Python `smtplib` + `email.mime` background thread worker with anti-spam compliance headers (`Message-ID`, `Date`, `Auto-Submitted`, `X-Mailer`, `Reply-To`)
* Flask CORS support for cross-origin API integration

### Database

* TiDB Cloud (Sole Database)
* MySQL-compatible SQL connector (`pymysql` with TLS/SSL encryption)
* Relational schema with foreign keys (`users` -> `trips` -> `trip_members`, `trip_invitations`, `moments`) and parameterized SQL queries
* Built-in connection lifecycle management with automatic reconnect on drop
* Graceful error handling: connection or query failures return friendly 503 JSON responses without leaking credentials or internal stack traces

### Image Storage

Images are stored in a private Cloudflare R2 bucket.

```text
Cloudflare R2
└── trip-moments/
    └── trips/<trip_id>/moments/<moment_id>.<extension>
```

The browser uploads images directly to R2 using a short-lived presigned PUT URL generated by Flask (with a bulletproof backend direct streaming upload endpoint as fallback).

TiDB stores the R2 object key (`photo_key`), not the image binary and not a permanent public URL.

R2 credentials must remain server-side and must never be exposed to the frontend.

## 4. Core Data Model

### users

Represents an individual traveler account.

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    email VARCHAR(255) NOT NULL UNIQUE,
    username VARCHAR(100) NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### trips

Represents a trip / journey created by a traveler.

```sql
CREATE TABLE trips (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NULL,
    name VARCHAR(255) NOT NULL,
    start_date DATE NULL,
    end_date DATE NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

* Unauthenticated/demo trips have `user_id = NULL`.
* Registered users see their own trips and trips where they are enrolled in `trip_members`.

### moments

Represents a single captured moment (postcard print, footnote, or both).

```sql
CREATE TABLE moments (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    trip_id BIGINT NOT NULL,
    user_id BIGINT NULL,
    author_name VARCHAR(100) NULL,
    caption TEXT NULL,
    photo_key VARCHAR(500) NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    latitude DECIMAL(10, 7) NULL,
    longitude DECIMAL(10, 7) NULL,

    FOREIGN KEY (trip_id) REFERENCES trips(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL
);
```

### trip_members

Represents travelers who are members of a shared trip.

```sql
CREATE TABLE trip_members (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    trip_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    role ENUM('creator', 'member') NOT NULL DEFAULT 'member',
    can_add_moments BOOLEAN NOT NULL DEFAULT TRUE,
    can_edit_moments BOOLEAN NOT NULL DEFAULT TRUE,
    can_delete_moments BOOLEAN NOT NULL DEFAULT TRUE,
    joined_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    UNIQUE KEY unique_trip_user (trip_id, user_id),
    FOREIGN KEY (trip_id) REFERENCES trips(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

### trip_invitations

Represents invitations to join a shared trip.

```sql
CREATE TABLE trip_invitations (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    trip_id BIGINT NOT NULL,
    inviter_id BIGINT NOT NULL,
    invitee_id BIGINT NULL,
    invite_type ENUM('direct', 'link') NOT NULL DEFAULT 'direct',
    token VARCHAR(64) NOT NULL UNIQUE,
    status ENUM('pending', 'accepted', 'declined', 'revoked', 'expired') NOT NULL DEFAULT 'pending',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    expires_at TIMESTAMP NULL,

    FOREIGN KEY (trip_id) REFERENCES trips(id) ON DELETE CASCADE,
    FOREIGN KEY (inviter_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (invitee_id) REFERENCES users(id) ON DELETE CASCADE
);
```

## 5. Entity Relationship

```text
users
  │
  ├── 1 : N (owns) ────────────► trips
  │                                │
  ├── 1 : N (member) ─► trip_members ◄── N : 1
  │                         │
  ├── 1 : N (invitations) ─► trip_invitations ◄── N : 1
  │                         │
  └── 1 : N (authors) ────────► moments ◄── N : 1
```

* One user can create trips (role: `creator`) or join existing trips (role: `member`).
* Moments permanently snapshot `author_name` upon creation.
* If a member leaves the trip, their moments and author attribution remain permanently intact.
* Deleting a trip (creator only) cascades and removes the trip, its members, invitations, and moments.

## 6. API Structure

The backend exposes simple, predictable REST JSON endpoints.

### Authentication

```text
POST   /api/auth/register      - Register new account with email, password, username
POST   /api/auth/login         - Authenticate user, returns signed bearer token
GET    /api/auth/me            - Retrieve profile of authenticated user
POST   /api/auth/logout        - Stateless client session termination
DELETE /api/auth/account       - Purge account, trips, moments, and R2 images
```

### Trips

```text
GET    /api/trips              - List trips for current user (with moment count, is_shared, members_summary, user_role)
POST   /api/trips              - Create a new trip (creator auto-added to trip_members)
GET    /api/trips/<trip_id>    - Retrieve details for a single trip (with user_role, is_creator, permissions)
DELETE /api/trips/<trip_id>    - Delete trip and all its moments & R2 images (creator only)
POST   /api/trips/<trip_id>/leave - Leave shared trip (member only)
```

### Moments

```text
GET    /api/trips/<trip_id>/moments    - List chronological moments for a trip with presigned photo URLs and author attributions
POST   /api/trips/<trip_id>/moments    - Create a moment (snapshots author_name & user_id)
DELETE /api/moments/<moment_id>        - Delete entire moment (enforces creator or own-moment delete permission)
DELETE /api/moments/<moment_id>/photo  - Delete only the photo (preserving footnote caption)
DELETE /api/moments/<moment_id>/footnote - Delete only the footnote caption (preserving photo)
```

### Sharing & Invitations

```text
GET    /api/trips/<trip_id>/members          - List members with roles and permissions
PATCH  /api/trips/<trip_id>/members/<user_id> - Update member permissions (creator only)
DELETE /api/trips/<trip_id>/members/<user_id> - Remove member from trip (creator only)
GET    /api/users/search                     - Search travelers by email or username
GET    /api/trips/<trip_id>/invitations      - List pending invitations (creator only)
POST   /api/trips/<trip_id>/invitations      - Create direct invitation or shareable invite link (creator only)
DELETE /api/trips/<trip_id>/invitations/<id> - Revoke an invitation (creator only)
GET    /api/invitations/pending              - List user's pending incoming invitations
GET    /api/invitations/<token>              - Preview invitation details without exposing memories
POST   /api/invitations/<token>/accept       - Accept invitation and join trip as member
POST   /api/invitations/<token>/decline      - Decline invitation
```

### Image Uploads

```text
POST   /api/uploads/presign    - Generate short-lived presigned PUT URL for browser-to-R2 upload
POST   /api/uploads/direct     - Direct multipart/form-data streaming upload via backend
PUT    /api/uploads/local-put  - Local filesystem mock upload endpoint for offline dev
```

### Health & Monitoring

```text
GET    /api/health             - Health check / keep-alive ping for server hosting (Render)
GET    /api/ping               - Alias ping endpoint
```

## 9. PWA Architecture

The application is installable as a Progressive Web App.

* `manifest.json`: Defines app name ("Postcards & Little Footnotes"), theme color (`#f7f4ec`), background color (`#efece3`), display mode (`standalone`), and icon set.
* `service-worker.js`: Caches core static assets (HTML, CSS, JS) under `postcards-shell-v6` to ensure fast loading and offline shell availability.

## 10. Image Handling & Storage

Cloudflare R2 is the authoritative image object store.

Upload workflow:

1. User selects or drags a photo. If format is HEIC/HEIF (common on iOS/macOS), `heic2any.min.js` automatically converts it to JPEG on-demand in the browser via WebAssembly.
2. Frontend initiates upload by requesting a presigned PUT URL from `/api/uploads/presign`.
3. Flask validates file metadata (MIME type, extension, size limit) and generates an object key: `trips/<trip_id>/moments/<uuid>.<ext>`.
4. Browser uploads directly to R2 using the presigned URL.
5. If browser preflight/CORS encounters issues, frontend automatically falls back to `/api/uploads/direct` for direct backend streaming.
6. The moment record is inserted into TiDB containing `photo_key`.
7. When displaying moments, Flask generates short-lived presigned GET URLs (`generate_presigned_download_url`).

## 11. Security Principles

* **Secret Isolation**: All credentials (TiDB password, Cloudflare R2 access keys, SMTP passwords, Secret Key) remain server-side in `.env`.
* **Password Security**: Passwords hashed using Werkzeug secure password hashing (PBKDF2/Argon2).
* **Token Security**: Session auth tokens signed using `URLSafeTimedSerializer` with cryptographic salt and expiration.
* **SQL Injection Prevention**: All SQL queries use parameterized queries via `pymysql`.
* **Data Isolation**: Database queries are strictly scoped by `user_id` and trip membership.
* **Granular Permissions**: Member permissions (`can_add_moments`, `can_edit_moments`, `can_delete_moments`) enforced at backend API level.
* **Direct Presigned Upload Security**: Direct browser-to-R2 uploads are cryptographically signed with HMAC-SHA256 (AWS SigV4). The signature is strictly bound to a single randomized UUID path and exact Content-Type, expires in 15 minutes (900s TTL), and never exposes secret keys to the client.
* **Complete Data Purge**: Account deletion comprehensively removes all user trips, moments, memberships, and R2 image objects.

## 13. Architectural Principle

Prefer the simplest implementation that correctly supports the core experience.

Do not introduce a framework, library, service, database table, abstraction, or architectural pattern unless it solves a real problem in the application.
